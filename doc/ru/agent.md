# Агент-программист

В TermIDE встроен агент-программист: панель, где вы описываете задачу
обычными словами, а языковая модель выполняет её, читая файлы, изменяя их и
запуская команды в вашем проекте. Всё, что может что-то изменить, сначала
спрашивает у вас разрешение.

Открывается по `Alt+A`, через **Окна → Агент** или из палитры команд
(**Open Agent**).

## Настройка модели

Агент работает с любым сервером, совместимым с API OpenAI. Это покрывает
локальные серверы (llama.cpp, Ollama, vLLM, omlx) и большинство облачных
шлюзов. Без настроенной модели панель не открывается и сообщает об этом.

```toml
[agent]
base_url = "http://127.0.0.1:10000/v1"
model = "Qwen3.8-Flash-Next-oQ4e-mtp"
context_window = 32000
max_tokens = 4096
reasoning = false            # передавать reasoning_effort моделям, которые его понимают
api_key_env = "OPENAI_API_KEY"   # имя переменной, а не сам ключ
```

Ключ API читается из переменной окружения, названной в `api_key_env`, поэтому
файл настроек никогда не содержит секрета. Локальным серверам ключ обычно не
нужен, оставьте переменную незаданной.

## Работа с панелью

Сессия занимает панель, поле ввода находится внизу. Заголовок панели — ваш
первый запрос, поэтому несколько панелей агента различимы с одного взгляда;
до первого запроса в заголовке стоит рабочий каталог. Своё название сессии
можно дать через меню панели `[≡]` → **Переименовать сессию**, и дальше в
заголовке будет оно.

В том же меню есть **Новая сессия**, которая начинает пустую, и **Открыть
сессию**, которая показывает сессии этого проекта, новые сверху, с пометкой
`●` у текущей, чтобы вернуться к отложенной работе. Переключение ждёт текущую
задачу: если агент работает, сначала остановите её по `Esc`.

| Клавиша | Действие |
|---|---|
| `Enter` | Отправить. Пока агент работает, текст встаёт в очередь на следующий ход |
| `Shift+Enter`, `Alt+Enter`, `Ctrl+J` | Перевод строки в поле ввода |
| `Esc` | Остановить работу; если ничего не выполняется, очистить ввод |
| `Ctrl+O` | Развернуть или свернуть все вызовы инструментов |
| `Ctrl+↑` / `Ctrl+↓`, `PageUp` / `PageDown` | Прокрутка сессии |
| `Ctrl+Home` / `Ctrl+End` | В начало или обратно к слежению за новыми строками |

Каждый вызов инструмента занимает одну строку: инструмент, над чем он
работал, и результат. Щелчок или `Ctrl+O` раскрывает полный вывод. Панель
следит за новыми строками, пока вы не прокрутите вверх, и возобновляет
слежение, когда вы вернётесь вниз.

Статусные чипы показывают режим разрешений, модель, занятую долю контекстного
окна, признак работы и число сообщений в очереди.

## Инструменты

У агента четыре инструмента.

- **read** возвращает файл с номерами строк, длинные файлы читаются по частям.
- **edit** заменяет уникальный фрагмент текста в файле и показывает diff.
- **write** создаёт файл или полностью заменяет его содержимое.
- **bash** выполняет команду в каталоге проекта, передавая вывод по мере
  появления. У длинного вывода сохраняются начало и конец, а полный лог
  пишется в файл, который агент может прочитать.

Поиск выполняется через `bash` привычными средствами (`rg`, `find`), а не
отдельным инструментом.

## Разрешения

Ничего, что меняет проект, не происходит без вашего согласия. Когда агент
хочет сделать что-то ещё не разрешённое, диалог предлагает четыре ответа:
разрешить один раз, разрешить на сессию, разрешить всегда или запретить.
«Разрешить всегда» дописывает правило в `.termide/config.toml` проекта.

Правила задаются по инструментам. Среди совпавших побеждает самое строгое,
поэтому `deny` всегда сильнее `allow`:

```toml
[agent.permissions]
mode = "ask"        # ask | accept-edits | auto

[agent.permissions.bash]
"cargo *"     = "allow"
"git status*" = "allow"
"git push*"   = "ask"
"rm -rf *"    = "deny"

[agent.permissions.edit]
"src/**" = "allow"
".env"   = "deny"

[agent.permissions.read]
"**/.env*" = "deny"
```

В шаблоне `*` означает любой текст, а начальное `**/` необязательно, поэтому
`**/.env*` совпадает и с `.env` в корне проекта. Команды оболочки проверяются
по частям: для `cargo build && rm -rf target` нужны разрешения на обе половины,
а запрет любой половины останавливает всю команду. Подстановка команд
(`$(…)`, обратные кавычки) не разрешается автоматически никогда.

Режим решает судьбу всего, что не покрыто правилами:

- **ask** (по умолчанию) спрашивает перед каждым изменением и каждой командой.
- **accept-edits** дополнительно позволяет изменять и создавать файлы внутри
  проекта без вопросов; команды оболочки по-прежнему спрашивают.
- **auto** разрешает всё. Используйте только там, где ошибка ничего не стоит,
  например в контейнере или временной копии репозитория.

Две вещи не спрашивают ни в одном режиме: чтение файла внутри проекта и
короткий список команд, которые только смотрят (`ls`, `cat`, `rg`,
`git status`, `find` без `-delete` и `-exec` и подобные). Перенаправление
вывода лишает команду этой поблажки.

## Инструкции проекта

Агент читает `AGENTS.md` (или `CLAUDE.md` в том же каталоге) из каждого
каталога от корня файловой системы до вашего рабочего каталога, самый
конкретный последним, плюс глобальный `AGENTS.md` в каталоге настроек
TermIDE. Опишите там соглашения проекта, и агент будет им следовать. Файлы
больше 32 КиБ пропускаются.

## История сессий

Каждая сессия пишется в журнал в формате JSON Lines, по файлу на сессию, в
подкаталог `agent` рядом с сохранённой раскладкой проекта в каталоге данных
TermIDE. Когда сессия приближается к пределу контекстного окна модели, агент
заменяет старую часть сводкой, которую пишет сам, и сохраняет недавние
сообщения дословно; панель сообщает об этом.

Панель агента не восстанавливается при открытии сохранённой раскладки TermIDE.
Откройте её заново по `Alt+A` и выберите нужную сессию через **Открыть
сессию**.
